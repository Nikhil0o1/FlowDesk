# Feature Status

What's built, how complete it is, and where the few placeholders are. ✅ = implemented end-to-end (UI → API → DB → permissions → notifications/email/realtime where applicable) and exercised against the running stack.

## Authentication & onboarding

| Feature | Status | Notes |
| --- | --- | --- |
| Email/password login | ✅ | bcrypt, rate-limited, audit-logged |

| No public signup | ✅ | No signup route/page; accounts only via invites |
| JWT access + rotating refresh | ✅ | httpOnly cookie, family-based **reuse detection** (tested) |

| Existing-user invites | ✅ | Accept link + in-app notification; no password change (tested) |
| Login page styling | ✅ | Pastel gradient, centered card, Google button, "or" divider, forgot password, no signup link |

## Cron jobs

All 8 implemented, run via APScheduler, every execution logged to `cron_job_logs` (visible in the admin panel): due-date reminders, overdue notifications, abandoned-timer stop, daily digest, recurring task generation, sprint completion reminder, expired invite cleanup, GitHub sync fallback (placeholder).

## Search & filters

Global Ctrl-K command palette searching tasks / projects / comments / users (access-scoped), plus full task filtering (assignee, creator, due today/week/overdue, priority, status, sprint, project, type, label) and sorting.

## Admin panel

Platform overview (counts), organization list with metadata + aggregate usage, create-org-with-owner-invite, disable/enable, platform audit log, cron log viewer. Separate `/admin` layout; superadmins land there after login.

## Audit logging

Org-scoped (owners: Settings → Audit log) and platform-scoped (superadmin) covering login/security events, invites, role changes, member removal, workspace/project/space lifecycle, sprint lifecycle, GitHub config changes, superadmin actions.

## Known placeholders / future work

- **GitHub sync fallback** polls nothing yet (documented above).
- **Billing** is metadata only (`plan`, `seats`) by design ("billing placeholder").
- **Direct messages**: schema supports `is_direct` channels; no DM UI yet.
- **S3 storage**: implemented but requires `pip install boto3` + `S3_*` env to activate.
- **Email digest/notification preferences** per user are not configurable yet (all on).
- Tests cover the backend core; no frontend component tests yet.
